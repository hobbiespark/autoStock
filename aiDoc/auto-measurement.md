- 거래일 07:30부터 앱이 Windows 유휴 절전을 막는다(그 전 동작: 08:30 ACTIVE부터). 장전 실측이 돌고, 08:30 장 대응 시작 전에 PC가 다시 잠들지 않게 하기 위해서다. 10/7 저녁~10/8 아침에 PC가 네 번 잠들었다.

## 3. 설정(`application.yml`)

```yaml
execution:
  tr-probe:
    enabled: true
    from: 2026-10-08             # 이 날부터 매 거래일. 하루만 재려면 until을 같은 날로
    at: "09:30"
    symbol: "069500"
    discount-pct: 15
    fill-round-trip-days: MONDAY # 체결 왕복 요일, 비우면 안 함
    notify-success: false        # 점검이 모두 맞으면 로그만
    output-dir: ../data/measured/tr_probe
  pre-open-probe:
    enabled: true
    from: "07:30"
    to: "08:40"
    symbols: "005930,069500"
    output-dir: ../data/measured/pre_open

autostock:
  ws:
    order-notice-capture:
      enabled: true
      dir: ../data/measured/ws_orders
  session:
    keep-awake-from: "07:30"     # 비우면 ACTIVE(08:30~16:00) 동안만
```

- 끄기: 각 `enabled: false`, 장전 절전 방지는 `keep-awake-from: ""`(재기동 필요).
- `execution.tr-probe`의 `date`·`fill-round-trip`(하루짜리 설정)은 없어졌다. 하루만 재려면 `from`·`until`을 같은 날로 둔다.

## 5. 버린 대안

- **매일 체결 왕복:** 매일 수수료가 들고 브로커 잔고가 잠깐 바뀐다. 형식 감시는 지정가·취소로 충분해서 월요일만 한다(빠지면 같은 주 다음 거래일).
- **빠진 날을 설정으로 메우기:** 요일을 하루 더했다가 사람이 되돌리는 방식은 앱 밖 일이 남는다. 앱이 이번 주 요약을 보고 스스로 메운다(10/12 사용자 지시: "앱 자체에서 예약된 작업이 수행되어야 함").
- **정상이어도 매일 텔레그램:** 하루 두 번 "정상"은 소음이다. 어긋날 때만 보낸다(`notify-success`로 켤 수 있다).
- **결과를 `docs/measured`에 매일:** 매일 25개 파일이 커밋 소음이 된다. 근거로 쓸 날만 골라 옮긴다.
- **WS 원문을 앱 로그에:** 로그 소음이 크고 보존 기간(로그 회전)에 묶인다. 별도 파일로 둔다.
- **장전 실측을 Claude 예약 작업으로:** 클라우드 세션이 PC에 닿으려면 데스크톱 앱이 켜져 있어야 하고, 앱 토큰·유량 제한기와 엇갈린다. 앱 안에서 한다(`market-hours-automation.md` 4절과 같은 이유).

## 6. 함정과 주의

- 장전 실측은 PC가 깨어 있어야 돈다. 07:30 전에 잠들어 있으면 그날은 건너뛴다(전원 설정 0.9).
- 주문 경로 점검은 모의 서버에서만 돈다. 실서버 주소로 바꾸면 ERROR 한 줄을 남기고 돌지 않는다.
- 매일 점검의 주문은 앱 장부를 거치지 않는다. 체결 왕복의 체결통보는 `brokerOrderId 매핑 없는 체결통보 무시` WARN 2줄로 남는다(정상).
- 첫 실행에서 `점검 실패`가 나오면 먼저 10/7 1차 실측 원문(`docs/measured/tr_probe_20261007_*`)과 비교한다. 기대(2절 ② 표)는 10/7 실측 기준이다.

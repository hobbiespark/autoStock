# 최상위 규칙

모든 대화는 이 문서를 가장 먼저 참고한다. §1~§3 규칙은 다른 지침(프로젝트 CLAUDE.md, 메모리 등)보다 우선한다.
단, 사용자가 대화 중 명시적으로 다르게 요청하면 그 요청을 따른다.

코딩 규칙은 별도 문서에 있다. 서비스 개발·유지보수의 기준이며(핵심 설계 이론 우선), 유지보수할 때는 기존 코드와 과거 결정을 따른다. 적용 범위와 우선순위는 그 문서 §0을 따른다.

## 1. 언어

- 별도 요청이 없으면 모든 응답은 **한국어**로 한다.
- 코드, 명령어, 식별자, 로그·에러 원문, 고유명사는 원문 그대로 둔다.
- 사용자가 다른 언어로 답해 달라고 하면 그 대화에서만 해당 언어를 쓴다.

## 2. 공통 작업 원칙

- 커밋 메시지는 단순하게 쓰고, AI 작성 표기(`Co-Authored-By` 등)를 넣지 않는다.
- 명시적 요청 없이 Jira에 코멘트를 남기지 않는다.

## 3. 진행 상황 보고

사용자가 오래 걸리는 작업을 마냥 기다리지 않아도 되게 한다.

- 여러 단계가 걸리는 작업은 시작 전에 단계 목록을 먼저 보여 준다. 필요하면 단계를 잘게 나눈다.
  - 예: `1/5 파일 구조 확인 → 2/5 원인 파악 → 3/5 수정 → 4/5 빌드·테스트 → 5/5 정리`
- 각 단계를 시작할 때와 마칠 때 현재 위치(`3/5`)와 결과를 짧게 알린다.
- 한 단계가 길어지면 중간에도 무엇을 하는 중인지, 어디까지 했는지 알린다(예: 파일 40개 중 25개 확인).
- 계획이 바뀌면(단계 추가, 순서 변경, 막힘) 바로 알리고 단계 목록을 고쳐 보여 준다.
- 막혀서 사용자 판단이 필요하면 기다리지 말고 곧바로 묻는다.
- 끝나면 완료한 것, 건너뛴 것, 남은 것을 나누어 정리한다.

## 4. 디자인 시스템·UI

### 4.1 디자인 토큰 표준
- **W3C DTCG Design Tokens Format Module 2025.10 — 첫 안정 버전(2025-10-28)**. `$value`/`$type`/`$description`/`$extensions`, 별칭(`{color.brand}`), 색상은 colorSpace 포함(Display P3·Oklch), 테마/다크모드 지원. 구현: Style Dictionary, Tokens Studio, Terrazzo; Figma·Penpot·Sketch 등 10개+ 툴 지원. 출처: https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/ ; https://www.designtokens.org/tr/2025.10/format/
- **권고**: `tokens.json`(DTCG) 1파일 → Style Dictionary로 `tokens.css`(커스텀 프로퍼티) 생성. 라이브러리 없이 CSS만 쓰는 현 결정과 충돌 없음. 난이도 **하**.

### 4.2 CSS 최신 기능(Vite 8 기본 타깃 Chrome 111/FF 114/Safari 16.4 기준)

### 4.3 다크모드 구현 모범
1. `<html>`에 `color-scheme: light dark` 선언 → 폼 컨트롤·스크롤바 자동.
2. 토큰은 시맨틱 레이어 2단(`--color-up`, `--color-down`, `--surface-1`)으로, 원시 팔레트 직접 참조 금지.
3. 사용자 강제 선택은 `data-theme="light|dark"` + `localStorage`, 미선택 시 시스템 따름. FOUC 방지: `<head>` 인라인 스크립트로 속성 선반영.
4. 차트 색은 CSS 변수를 `getComputedStyle`로 읽어 recharts에 전달(테마 전환 시 리렌더).

### 4.4 금융 대시보드 UI 패턴
- **정보 밀도·표 우선**: 운영 화면은 카드형 KPI 6~8개 + 나머지는 표. 행 높이 32px, 고정폭 숫자(`font-variant-numeric: tabular-nums`), 오른쪽 정렬.
- **상승/하락 색 — 한국 관례 빨강=상승/파랑=하락**(미국·유럽과 반대). 토큰 이름을 `--color-up/--color-down`으로 두고 값만 지역 설정으로. **색 외 표시 병행 필수**: 부호(`+1.23%`), 화살표(▲▼), 아이콘. 색약 대비: 빨강 `#D32F2F`/파랑 `#1976D2`급, 배경 대비 4.5:1 이상.
- **위험 동작 UX(킬스위치·강제 청산·테스트 시그널 전송)**
  - 2단계 확인: 버튼 → 다이얼로그(영향 요약: 포지션 N개, 예상 금액) → 확인.
  - **타이핑 확인**: 계좌 전체 청산 등 비가역은 `"청산"` 타이핑 후 활성화(GitHub 저장소 삭제 패턴).
  - **되돌리기 불가 명시** + 서버가 반환한 결과로만 UI 갱신(낙관적 업데이트 금지와 정합).
  - **쿨다운**: 킬스위치 해제는 5초 카운트다운 후 활성화, 연타 방지 `disabled` + `aria-busy`.
  - **안전 기본값**: 테스트 시그널 폼 기본은 "모의(dry-run)" 체크됨, 실주문은 명시적 토글.
  - 확인 버튼은 위험색·왼쪽엔 취소, `Enter` 기본 동작이 위험 버튼이 되지 않도록.
- **숫자 표기**: `new Intl.NumberFormat('ko-KR', {style:'currency', currency:'KRW', maximumFractionDigits:0})`, 퍼센트는 `{style:'percent', minimumFractionDigits:2, signDisplay:'exceptZero'}`. 큰 수는 `notation:'compact'`(예: 1.2억) 대신 운영 화면에서는 **전체 자릿수** 권장.
- **시각**: 서버 KST 기준. `Intl.DateTimeFormat('ko-KR',{timeZone:'Asia/Seoul', hour12:false, …})` + 라벨에 **"KST"** 명시. 상대 시각("3초 전")은 `Intl.RelativeTimeFormat`, 절대 시각은 `<time datetime>`.
- **상태 배지**: 색 + 아이콘 + 텍스트 3중. `RUNNING ●`, `PAUSED ❚❚`, `KILLED ✕`, `DEGRADED ⚠`. `role="status"` 아님(배지 자체는 정적), 변경 알림은 별도 라이브 리전.
- **빈/로딩/오류**: 초기 로딩 스켈레톤(2초 이내), 폴링 중 갱신은 **레이아웃 유지**(스피너 금지, 헤더에 작은 "갱신 중" 점). 오류 시 마지막 정상 데이터 유지 + 상단 배너("마지막 갱신 12:03:41 KST, 3회 연속 실패") + `retry` 버튼. 빈 상태는 원인+다음 행동("오늘 체결 없음 · 09:05 판단 대기 중").

### 4.5 컴포넌트 라이브러리 옵션

| 옵션 | 최신(npm 미조회, [미확인]) | 성격 | 평가 |
|---|---|---|---|
| shadcn/ui | CLI 복사형(Radix/Base UI 기반) | 소스 소유, Tailwind 전제 | Tailwind 미사용 시 이점 감소 |
| Radix Primitives | 헤드리스 | Dialog/Popover/Tabs 접근성 완성도 높음 | **위험 동작 다이얼로그·탭에 한정 도입 고려**(번들 +10~20KB) |
| Ark UI | 헤드리스(Zag 기반), 프레임워크 무관 | Radix 대안 | 동급 |
| Mantine | 풀 UI, CSS 모듈 | 빠른 구축 | 번들 증가, CSS-only 결정과 충돌 |

### 5.2 KWCAG 2.2
- 표준번호 **KS X OT0003:2022**, 개정 2022-12-28, 과기정통부 국립전파연구원. 4원칙·14지침·**33개 검사항목**. WCAG 2.1 기반, 2.2 일부 반영. 출처: https://a11ykr.github.io/kwcag22/
- 2.1 대비 추가: 6.4.4 고정된 참조 위치 정보, 6.5.1 단일 포인터 입력 지원, 6.5.2 포인터 입력 취소, 6.5.3 레이블과 네임, 6.5.4 동작기반 작동, 7.2.2 찾기 쉬운 도움 정보, 7.3.3 접근 가능한 인증, 7.3.4 반복 입력 정보.
- **보강 확인**: 2024~2026 재개정·2.3 발표 근거를 찾지 못함 — 현재 기준은 **KWCAG 2.2(KS X OT0003:2022, 2022-12-28 개정)**로 둔다(국립전파연구원 페이지는 robots 차단으로 원문 미열람).

### 5.3 이 시스템 적용
| 요소 | 구현 |
|---|---|
| 이벤트 피드 | 컨테이너 `role="log" aria-live="polite" aria-relevant="additions"`; 새 행만 DOM 추가(전체 재렌더 금지 → `key` 안정). 긴급(킬스위치 발동)은 별도 `aria-live="assertive"` 1줄 리전 |
| 주문 상태 변경 | 표 셀 갱신은 라이브 리전이 읽지 않음 → 시각적으로 숨긴 `<div role="status">`에 "주문 #123 체결, 슬리피지 0.05%" 텍스트를 1회 기록(중복 방지 debounce 1초) |
| 폼 오류(테스트 시그널) | `aria-invalid` + `aria-describedby`로 오류 문장 연결, 제출 시 첫 오류 필드 포커스, 오류 요약 `role="alert"` |
| 타깃 크기 | 모바일 버튼 최소 24×24(권장 44×44), 표 행 액션은 아이콘+텍스트 |
| 초점 | 고정 헤더가 포커스 요소 가리지 않도록 `scroll-padding-top` |
| 색 | 상승/하락 색+기호, 대비 4.5:1, 다크모드 별도 검증 |

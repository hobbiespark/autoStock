### 1-2. 공식 오류코드(유량 제한 포함)

- 사실(스펙 JSON `error_codes` 원문):
  - `1700` "허용된 API 요청 개수를 초과하였습니다. 유량={?}, API ID={?}" — **TR(API ID) 단위 유량 제한**
  - `1701` "허용된 전체 요청 개수를 초과하였습니다. 총유량={?}" — **전체(계정) 단위 총유량 제한**
  - `1702` "허용된 그룹 요청 개수를 초과하였습니다. 총유량={?}, API_ID={?}" — **그룹 단위 유량 제한**
  - `1687` "재귀 호출이 발생하여 API 호출을 제한합니다"
  - `8005` "Token이 유효하지 않습니다", `8010` "Token을 발급받은 IP와 서비스를 요청한 IP가 동일하지 않습니다" (토큰은 발급 IP에 바인딩)
  - `8104` "모의투자에서 지원하지 않는 API 입니다.", `8200` "법인 고객은 해당 API를 지원하지 않습니다"
- 사실(보강 확인): 공식 소개 페이지 — **"주문 TR: 1초당 5회", "조회 TR: 1초당 5회", "모의 투자 계좌별(토큰별) TR 1개당 국내주식 1초 1회"**([키움 소개](https://openapi.kiwoom.com/intro?dummyVal=0)). 스펙 JSON에는 수치 없음. 공식 Python 클라이언트 `iterate_pages()`는 연속조회 페이지 사이 기본 `page_delay_seconds=0.2`로 대기(서버 요청 간격 배려 목적, 주석 명시).
- 출처: `kiwoom/_data/kiwoom_api_spec.json` error_codes; `kiwoom/core/client.py` L142~185
- 확인일: 2026-10-01
- 시스템 함의: 현재 "TR당 초당 1건"은 실측(1700) 기반이며 공식 수치 아님 → 유지하되 **1701(총유량)·1702(그룹)도 별도로 파싱**해 백오프해야 함. 1700만 처리하면 다중 TR 동시 호출 시 1701/1702로 실패할 수 있음. 토큰은 발급 IP 고정이므로 서버 이전/NAT 변경 시 재발급 필요.
- 확실도: 높음(오류코드), 낮음(수치 — 미확인)

### 1-3. 토큰(au10001) 만료 정책

- 사실: 응답 필드 `expires_dt`(만료일, 예시 "20241107083713" = yyyyMMddHHmmss), `token_type`("bearer"), `token`. 공식 클라이언트는 `expires_dt`를 파싱해 로컬 캐시하고 401/8005 시 1회 재발급 후 재시도. 유효기간은 스펙 JSON에는 없으나 **공식 서비스 안내에 "접근토큰의 유효기간은 24시간"**(보강 확인, [서비스 안내](https://openapi.kiwoom.com/intro/serviceInfo)).
- 사실: 토큰 폐기 API `au10002` `/oauth2/revoke` 존재.
- 출처: 스펙 JSON `접근토큰 발급(au10001)`, `kiwoom/core/auth.py` L130~160
- 확인일: 2026-10-01
- 시스템 함의: TTL을 상수로 두지 말고 `expires_dt` 기준으로 만료 N분 전 선제 갱신 + 8005/401 수신 시 1회 재발급-재시도. WebSocket LOGIN 실패도 동일 토큰 재발급 경로로 처리(공식 ws_client와 동일 패턴).
- 확실도: 높음(필드), 미확인(TTL 수치)

### 1-4. 주문 TR과 `dmst_stex_tp` (NXT/SOR)

- 사실: 계좌/체결 계열 거래소 구분 파라미터는 TR마다 다름:
  - `ka10075`(미체결), `ka10076`(체결): `stex_tp` "0:통합, 1:KRX, 2:NXT"
  - `kt00007`(계좌별주문체결내역상세), `kt00009`(계좌별주문체결현황): `dmst_stex_tp` "%:(전체), KRX, NXT, SOR"
  - `kt00018`(계좌평가잔고내역): `dmst_stex_tp` "KRX, NXT" (SOR/전체 값 없음)
- 사실: 실시간 `00`(주문체결) 응답 FID `2134` 거래소구분 "0:통합,1:KRX,2:NXT", `2135` 거래소구분명, `2136` SOR여부 "Y,N". `0B`(주식체결) FID `9081` 거래소구분, `290` 장구분 "1:장전 시간외, 2:장중, 3:장후 시간외".

### 1-5. 시간외/애프터마켓 주문 지원

- 사실: 스펙(2026-09-04 소스 기준)의 `trde_tp`에 `61 장시작전시간외`, `81 장마감후시간외`, `62 시간외단일가`가 여전히 존재. 실시간 `0s`(장시작시간) `215` 장운영구분 코드도 `c: 시간외 단일가 시작(16:00)`, `d: 시간외 단일가 종료(18:00)` 등 **구(舊) KRX 시간외단일가(16:00~18:00) 체계**를 그대로 기재하며, NXT 코드(`P~V`: NXT 프리마켓/메인/애프터마켓 시작·종료 알림)는 포함. KRX 애프터마켓(2026-09-14 개장, 16:00~20:00, §3) 관련 코드·주문유형은 스펙에 **없음**.
- 사실: 타사 사례 — KB증권 API는 KRX 애프터마켓 시행에 맞춰 시간외단일가 주문 TR(SSAM1801/1802/1805)을 제거하고 KRX/NXT 예상체결 필드를 분리(커뮤니티 MCP PR 기준).
- 키움의 KRX 애프터마켓 REST 주문 지원 방식(별도 trde_tp 신설인지, `0:보통`+시간대로 처리인지)은 **미확인** — 공식 공지 페이지(openapi.kiwoom.com/m/board/…)가 JS 렌더링이라 본문 추출 실패.
- 출처: 스펙 JSON `kt10000`, `장시작시간(0s)`; https://github.com/nkwoo/kbsec-mcp/pull/1
- 확인일: 2026-10-01
- 시스템 함의: 장외 대기 시간(08:30~16:00)을 넘어서는 애프터마켓(16:00~20:00) 참여는 키움 공식 스펙 갱신 확인 전까지 보류. `0s` 실시간의 `215` 코드 매핑을 하드코딩하지 말고 미지 코드는 로그+무시로 처리(신규 코드 추가 대비). 62(시간외단일가) 주문은 KRX 제도 폐지로 실전에서 거부될 수 있으므로 사용 금지 플래그.
- 확실도: 중간

### 1-6. WebSocket 스펙

- 사실: 도메인 `wss://api.kiwoom.com:10000`, 모의 `wss://mockapi.kiwoom.com:10000`, 경로 `/api/dostk/websocket`(국내), `/api/us/websocket`(미국). 등록 `trnm: REG`, 해지 `REMOVE`, `grp_no`, `refresh`(1: 기존 등록 유지, 기본), `data[{item,type}]`. 실시간 수신 시 `trnm: REAL`.
- 사실: 서버가 `PING`(문자열 또는 `{"trnm":"PING"}`)을 보내며 공식 클라이언트는 **동일 메시지를 그대로 에코**하고 `ping_interval=None`(라이브러리 자체 ping 비활성). 국내 실시간 타입 19종(00,04,0A,0B,0C,0D,0E,0F,0G,0H,0I,0J,0U,0g,0m,0s,0u,0w,1h), 미국 4종(F4,F5,FE,FT). WebSocket API 총 31개(조건검색 8개 포함).
- 사실: `00`(주문체결)은 item 등록 없이 토큰 발급 계좌의 주문/체결 이벤트가 수신됨(스펙 개요 문구).
- 출처: 스펙 JSON, `kiwoom/core/ws_client.py`
- 확인일: 2026-10-01
- 시스템 함의: Java WS 클라이언트에서 서버 PING을 텍스트 프레임 그대로 회신(웹소켓 프로토콜 레벨 ping/pong이 아님)해야 끊김 방지. 재연결 시 `refresh=1` 기본이므로 재등록 중복 주의. 등록 항목 수 제한은 공식 스펙에 없음(미확인).

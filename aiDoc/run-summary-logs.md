## 2. 결정과 근거

### `C3LiveStrategy`
- `run()`(09:05 스케줄)이 `execute()`가 돌려준 요약을 INFO 1줄로 남긴다.
  - 국면 ON 예:
    `C3 판단 2026-10-01 — 국면 ON(069500 종가 11000 / SMA200 10005) · 매수 1 · 매도 1 · 보유 유지 1 · 미진입 1 · 주기 전 0 · 데이터 부족 0 · 오류 1 · 다음 판단 2026-10-22부터 · 다음 스케줄에 재판단 1종목`
  - 국면 OFF 예:
    `C3 판단 … — 국면 OFF(…) · 신규 판단 보류 · 강제 청산 신호 N · 오류 N`
- 비활성·운영 상태·휴장일로 건너뛰면 요약을 남기지 않는다. 운영 상태·휴장일 스킵은 기존 로그가 있다.
- **"다음 판단"을 정하는 방법:**
  - 판단한 종목의 (판단일 + 21일) 중 가장 이른 날을 쓴다.
  - 판단 기록이 없거나 오늘 실패한 종목은 "다음 스케줄에 재판단 N종목"으로 따로 센다. `isJudgmentDay`와 같은 기준이다.
  - 21일 주기 영속화(F-3)는 Phase 1에서 다룬다. 그 전까지는 재기동하면 다시 "재판단"으로 나온다.
- **매매에는 영향이 없다.** 판단, Signal·SignalDecision 발행은 그대로다. `decideOne`이 결과 분류(`Outcome`)를 돌려주게만 바꿨다.

### `IpoSyncScheduler`
- `syncNow()`가 `sync()` 요약을 INFO 1줄로 남긴다. 블랙리스트·매크로 수집과 같은 형식이다.
  - 예:
    `공모주 수집 완료 — 2026-09-17~2026-10-01 증권신고(지분증권) 3건(신규 딜 1·저장 생략 0·실패 1), 전체 딜 1건 상태 재계산`

### `PositionRestorer`
- `[실측]` 키 로그를 DEBUG로 낮췄다.
- 대신 해석 실패 WARN에 원소 키를 직접 싣는다. 예전 WARN은 "위 키 로그 참고"라고만 적었다.

## 3. 버린 대안과 보류

- **종목별 판단을 INFO로 각각 남기기:** 실행마다 5줄씩 늘어난다. 상세 근거는 이미 판단 근거 탭(DB)에 있고, 실행 확인에는 요약 1줄이면 충분하다.
- **로그 캡처로 테스트:** 기존 테스트에 그 방식이 없다. 대신 실행 본체가 요약 값을 돌려주게 하고(`execute()`·`sync()`, 패키지 공개), 그 값을 검증했다.
